Pre-Auth RCE On A D-Link Router - CVE-1-1

A walkthrough of discovering and exploiting a pre-auth stack-based buffer overflow in the D-Link DSL-224RTL CWMP service.

Overview#

I recently decided to take a deeper look at a router i found at home , D-link DSL-224 RTL . Although the device reached its End-of-Life (just a few months ago), these ISP-managed appliances remain widely deployed, making their management interfaces a prime target for finding vulnerabilities.

Extracting the firmware#

First, I needed to obtain the router’s binaries for further research, which I easily found on D-Link’s public FTP server.

My physical router runs firmware version 3.0.5. I initially wanted to emulate the latest firmware version, but the emulation process proved overly complicated for this specific device due to numerous hardware dependencies that would need to be patched. Therefore, I chose to start testing directly on my own physical router (not the best practice, I know!) and proceed with my investigation from there.

I executed binwalk on the firmware image and successfully extracted the entire SquashFS file system.

Mapping Attack surfaces#

Binary Mitigations#

Before getting into the code, I ran standard checks on the /sbin/tr069 binary (MIPS-32 Big Endian) to see what kind of mitigations was going to put up. The answer? Absolutely none.

  • RELRO: No RELRO
  • Stack Canary: None found
  • NX: Unknown (GNU_STACK missing)
  • PIE: No PIE (Fixed base address at 0x400000)
  • RWX: Has RWX segments

Classic embedded device binary , the real challenge here is that the architecture is MIPS that i unfimiliar with and the limits of the Vulnerable code itself .

Technical Analysis: Hunting for the Bug#

Tracing the execution flow for HTTP Digest authentication, I landed in a function sitting at 0x45628C in firmware version 3.0.5 (it shifted to 0x47909C in version 3.0.10, but the logic is identical).

This function is responsible for building an MD5 input string for the Digest auth validation. It does this by concatenating various fields from the HTTP Authorization header into a fixed-size stack buffer.

char *__fastcall sub_45628C(const char *a1, char *a2, int a3, int a4)
{
  char s[68];        // [sp+18h]
  char src[68];      // [sp+5Ch]
  char dest[200];    // [sp+A0h]  <-- Our target
  int v11;           // [sp+168h]

  memset(s,    0, 0x41);
  memset(src,  0, 0x41);
  memset(dest, 0, sizeof(dest));
  sub_456164(a1, s, a3, v11);
  sub_45605C(a1, src);
  
  sprintf(dest, "%s:%s:", s, a1 + 401);   // realm
  
  if (a1[953]) {                          // If 'qop' is present -> overflow path!
    strcat(dest, a1 + 545);               // cnonce   <-- no bounds check
    strcat(dest, ":");
    strcat(dest, a1 + 473);               // opaque   <-- no bounds check
    strcat(dest, ":");
    strcat(dest, a1 + 953);               // qop      <-- no bounds check
    strcat(dest, ":");
  }
  
  strcat(dest, src);                      // nc       <-- no bounds check
  do_md5_string(dest);
  strcpy(a2, dest);                       // secondary propagation
  return a2;
}
